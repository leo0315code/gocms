# GoCMS 部署指南

> 面向：Linux 服务器（CentOS / Ubuntu / Debian）单机部署
> 前置：已完成 `docs/01-设计文档.md` 的技术了解

---

## 一、部署前检查清单

上线前必须改的 4 项：

| 配置项 | 默认值 | 生产必须改成 |
| --- | --- | --- |
| `APP_ENV` | `development` | `production`（关闭详细错误页） |
| `ADMIN_PASS` | `Admin@123456` | 强随机密码（≥12 位，含大小写+数字+符号） |
| `APP_URL` | `http://localhost:8090` | 真实域名，如 `https://www.example.com`（影响 sitemap/RSS 绝对链接） |
| `DB_PASS` | `123456` | 强随机密码，且 MySQL 只监听 127.0.0.1 |

## 二、编译产物

Go 是静态编译，服务器上**不需要装 Go**。

```bash
# 在开发机（macOS）上交叉编译
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 \
  go build -trimpath -ldflags "-s -w" -o gocms-linux-amd64 ./cmd/gocms

# 或直接用 Makefile
make build-linux
```

产物约 11MB，单文件，无动态库依赖。ARM 服务器把 `GOARCH` 换成 `arm64`。

## 三、服务器初始化

### 3.1 建目录与用户

```bash
sudo useradd -r -s /sbin/nologin gocms
sudo mkdir -p /var/www/gocms/{uploads,.run}
sudo cp gocms-linux-amd64 /var/www/gocms/gocms
sudo cp .env /var/www/gocms/.env
sudo chown -R gocms:gocms /var/www/gocms
sudo chmod 600 /var/www/gocms/.env      # 配置含数据库密码，禁止其他用户读
sudo chmod +x /var/www/gocms/gocms
```

> 程序需要在**当前工作目录**下找到 `.env`、`themes/`、`web/`，所以必须 `cd /var/www/gocms` 后再启动，
> 或用 systemd 的 `WorkingDirectory` 指定。

### 3.2 同步必需目录

二进制之外，还要把这两个目录传上去（它们是运行时读取的，没有 embed）：

```bash
# themes/  前台主题（模板 + CSS/JS）
# web/     后台模板与静态资源
rsync -av themes web /var/www/gocms/
```

`docs/` 不需要上传，`cmd/` `internal/` 是源码，也不需要。

### 3.3 建库

```sql
CREATE DATABASE gocms CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'gocms'@'127.0.0.1' IDENTIFIED BY '强随机密码';
GRANT ALL PRIVILEGES ON gocms.* TO 'gocms'@'127.0.0.1';
FLUSH PRIVILEGES;
```

若要中文搜索准确，额外开启 ngram 分词：

```ini
# my.cnf
[mysqld]
ngram_token_size=2
```

建表、管理员、演示数据由程序首次启动时自动完成（`go:embed` 迁移 + seed）。

## 四、systemd 托管

`/etc/systemd/system/gocms.service`：

```ini
[Unit]
Description=GoCMS
After=network.target mysql.service
Wants=mysql.service

[Service]
Type=simple
User=gocms
Group=gocms
WorkingDirectory=/var/www/gocms
ExecStart=/var/www/gocms/gocms
Restart=always
RestartSec=3
StandardOutput=append:/var/www/gocms/.run/gocms.log
StandardError=append:/var/www/gocms/.run/gocms.log

# 基础加固
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ProtectHome=true
ReadWritePaths=/var/www/gocms/uploads /var/www/gocms/.run

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now gocms
sudo systemctl status gocms
sudo journalctl -u gocms -f
```

> `ReadWritePaths` 只放开 `uploads/` 和 `.run/`，其余目录只读 —— 即使被拿下也无法篡改程序与模板。

## 五、Nginx 反代

```nginx
server {
    listen 80;
    server_name www.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name www.example.com;

    ssl_certificate     /etc/letsencrypt/live/www.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/www.example.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;

    client_max_body_size 12m;          # 略大于 UPLOAD_MAX_MB

    # 静态资源直出，绕过 Go
    location ~ ^/(assets|uploads|admin/assets)/ {
        root /var/www/gocms;
        expires 7d;
        access_log off;
        add_header Cache-Control "public";
        try_files $uri =404;
    }

    location / {
        proxy_pass         http://127.0.0.1:8090;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_set_header   X-Forwarded-Host  $host;
        proxy_read_timeout 120s;
    }
}
```

### 三个必须注意的点

1. **不要做 `.html` 重写。** 伪静态由 Go 内部的 `stripHTMLExt` 处理。如果 Nginx 用
   `rewrite ^/(.*)\.html$ /$1 last;` 剥掉后缀，再叠上 Go 的处理逻辑会 404。

2. **`X-Forwarded-For` 必须透传。** 登录限流、留言限流都按 `ClientIP` 计数。
   程序已优先读 `X-Forwarded-For` / `X-Real-IP`，不透传的话所有请求会算成同一个 IP，
   一个人触发限流就会全员被锁。

3. **静态目录要 `try_files $uri =404;`。** `root` 指向项目根，如果不限制，
   攻击者可能通过 `..` 或直接请求路径读到 `.env`。更稳妥的做法是把 `assets`、`uploads`
   指向独立目录，或用 `location ~ ^/(assets|uploads)/[^/]+\.(php|sh|env)$ { deny all; }` 兜底。

### 上传目录安全

上传文件名是「ASCII 化 slug + 随机 hex + 原扩展名」，且扩展名在白名单内，
但 `uploads/` 仍在 web 根下，必须确保 **Nginx 不解析其中的脚本**：

```nginx
location ~* ^/uploads/.*\.(php|php5|phtml|sh|py|jsp)$ {
    deny all;
    return 403;
}
```

## 六、HTTPS 与 Cookie

生产环境启用 HTTPS 后，`.env` 里要开 `SESSION_SECURE`（若你的版本支持），
或确认程序在 `APP_ENV=production` 时会自动给 Cookie 加 `Secure`。
否则浏览器会拒绝在 HTTP 页面发送带 `Secure` 的 Cookie，导致登录后立刻掉线。

## 七、备份

### 数据库

```bash
# 每日 3:00 全量备份，保留 14 天
cat > /etc/cron.d/gocms-backup <<'EOF'
0 3 * * * gocms mysqldump -h127.0.0.1 -ugocms -p"$DB_PASS" \
  --single-transaction --routines --triggers gocms \
  | gzip > /var/backups/gocms-$(date +\%F).sql.gz
EOF

# 清理 14 天前
find /var/backups -name 'gocms-*.sql.gz' -mtime +14 -delete
```

`--single-transaction` 对 InnoDB 是热备，不锁表，后台可继续写。

### 上传文件

```bash
rsync -a --delete /var/www/gocms/uploads/ /var/backups/gocms-uploads/
```

上传文件与数据库**必须一起备份**，否则恢复后文章封面全部 404。

## 八、升级流程

```bash
cd /var/www/gocms

# 1. 备份（库 + uploads）
mysqldump ... | gzip > /var/backups/pre-upgrade.sql.gz
rsync -a uploads/ /var/backups/uploads-pre-upgrade/

# 2. 换二进制（themes/ 若有更新也一起换）
sudo systemctl stop gocms
sudo cp gocms-linux-amd64.new gocms
sudo chown gocms:gocms gocms && sudo chmod +x gocms

# 3. 启动（迁移会自动执行，schema_migrations 表记录版本）
sudo systemctl start gocms
sudo journalctl -u gocms -n 50

# 4. 冒烟测试
curl -sI https://www.example.com/ | head -1        # 200
curl -sI https://www.example.com/admin/login | head -1
```

迁移是幂等的：`schema_migrations` 表记录已执行版本，重复启动不会重跑。
**回滚**：`systemctl stop` → 换回旧二进制 → 恢复数据库备份 → `systemctl start`。

## 九、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动报 `connect: connection refused` | MySQL 没起 / 端口不对 | `systemctl status mysql`，核对 `.env` 的 `DB_HOST/DB_PORT` |
| 启动报 `Access denied for user` | 密码错 / 用户没授权 | 用 root 进库核对 `mysql.user`，确认 host 是 `127.0.0.1` 不是 `localhost` |
| 全站 500，日志 `no such template` | `themes/` 或 `web/` 没上传，或工作目录不对 | 确认 `WorkingDirectory=/var/www/gocms` 且 `themes/default/templates/` 存在 |
| `.html` 后缀 404 | Nginx 做了 `.html` 重写 | 删掉 rewrite 规则，原样透传 |
| 登录后立刻掉线 | HTTPS 下 Cookie `Secure` 与访问协议不匹配 | 确认访问的是 https，或检查 `APP_ENV` |
| 后台保存提示「表单过大或解析失败」 | Nginx `client_max_body_size` 太小 | 调到 12m 以上 |
| 中文搜索搜不到 | MySQL 未启用 ngram | 加 `ngram_token_size=2` 并重建全文索引 |
| 所有请求 IP 相同、限流误伤 | 未透传 `X-Forwarded-For` | Nginx 加 `proxy_set_header X-Forwarded-For` |
| 上传成功但图片 404 | Nginx 静态 root 路径错了 | 核对 `root /var/www/gocms;` 与 `uploads/年月/文件名` 实际路径 |

## 十、性能基线

单机 2C4G、MySQL 同机、SSR 渲染、无 OPcache 类缓存：

| 场景 | 预期 |
| --- | --- |
| 首页（含 3 轮播 + 6 卡片 + 侧栏） | 10~25ms |
| 文章详情（含相关推荐 + 上下篇） | 8~20ms |
| 后台列表（20 条/页） | 10~30ms |
| 连接池 | MaxOpen 50 / MaxIdle 20，够 500 QPS 量级 |

主要瓶颈会先出现在 MySQL；后续优化方向按优先级：

1. 给 `posts(status, published_at)` 已有复合索引，列表查询走索引没问题
2. 首页轮播/推荐/最新是 3 次独立查询，可加热点数据内存缓存（5 分钟）
3. 静态资源加 CDN
4. 多实例时把 Session 与限流迁到 Redis
