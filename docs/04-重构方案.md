# GoCMS v1.1 重构方案

> 目标：解决 v1.0 的三个工程痛点 —— 手写 SQL 难维护、后台路径写死、手写 CSS 维护成本高。
> 本文档先于代码编写，作为重构的执行依据与验收标准。

---

## 一、改造动因

| 问题 | v1.0 现状 | 影响 |
| --- | --- | --- |
| 数据访问 | repository 层 1979 行手写 SQL，`Scan` 与 `buildWhere` 遍布 | 加一个字段要改 4~5 处；拼 SQL 易错；无软删除/关联预加载 |
| 后台路径 | `/admin` 硬编码 **257 处**（Go 56 + HTML 195 + JS 6） | 无法隐藏后台入口，等于公开告诉扫描器「攻击面在这里」 |
| 样式 | 后台 607 行 + 前台 600 行手写 CSS，自带一套设计令牌 | 每个新组件都要手写样式；响应式要手算断点；组件无法复用 |

---

## 二、技术选型（已确认）

### 2.1 前端路线：保留 SSR + Tailwind + Alpine

**决策**：后台仍是 Go `html/template` 服务端渲染，不引入 React/Vue。

**理由**：

| 考虑点 | 说明 |
| --- | --- |
| 部署形态 | 保持「单二进制 + 静态目录」，不需要 Node 运行时，符合原设计 |
| 鉴权 | 继续用 Session Cookie + CSRF，不用为 SPA 重做 Token 鉴权 |
| SEO/首屏 | 后台无所谓，但前台也共用同一套 Tailwind 构建，风格统一 |
| 开发效率 | Tailwind 解决「写样式」，Alpine 解决「交互」，两者都是声明式、零构建配置负担 |
| 组件复用 | 通过 Go `{{template}}` 抽组件（表格、分页、表单控件），一次定义全站复用 |

**放弃 React/Vue 的代价**：复杂表格（虚拟滚动、列宽拖拽）需要自己拼。但 CMS 后台以表单和列表为主，实际用不到这类重组件。

### 2.2 ORM：GORM

**理由**：

- Go 生态占有率最高，文档与社区案例最全，交接成本最低
- `AutoMigrate`、软删除、关联预加载、钩子（BeforeSave 自动生成 slug）开箱即用
- 保留 `Raw()` 逃生口，复杂统计 SQL 仍可手写

**风险控制**：handler 层不动，只替换 repository 内部实现，接口签名保持一致。这样出问题能单文件回滚。

### 2.3 后台路径：`.env` 默认 + 后台可视化修改

**设计**：

```
优先级：数据库 settings 表（运行时可改） > .env ADMIN_PATH > 默认 "admin"
```

- `.env` 的 `ADMIN_PATH` 作为**初始值**，首次启动写入 settings 表
- 后台「系统设置 → 安全」可改，存库后**下一次请求即生效**（路由前缀在中间件里动态解析，不需要重启）
- 提供「遗留路径重定向」开关：默认开启，旧路径 302 到新路径，避免改完自己进不去
- 路径校验：只允许 `[a-zA-Z0-9_-]`，长度 2~32，不能与保留前缀（`a`/`c`/`p`/`t`/`assets`/`uploads`/`search`）冲突

## 三、改造清单

### 3.1 可配置后台路径

| # | 改动点 | 文件 |
| --- | --- | --- |
| 1 | 配置项 `ADMIN_PATH` | `internal/config/config.go` |
| 2 | 路径解析器（读库 + 校验 + 缓存） | `internal/adminpath/adminpath.go`（新增） |
| 3 | 路由注册改为动态前缀 | `internal/router/router.go` |
| 4 | 中间件：路径改写 + 遗留路径重定向 | `internal/middleware/middleware.go` |
| 5 | 模板统一取 `{{.AdminPath}}` | `web/admin/templates/*.html`（18 个） |
| 6 | Handler 内跳转统一用 `h.adminURL()` / `h.adminPath` | `internal/handler/*.go` |
| 7 | 设置页新增「安全」分组 | `web/admin/templates/settings.html` |
| 8 | 后台静态资源路径跟随前缀 | `internal/router/router.go` |

**关键实现**：路由不能再用 `mux.Handle("GET /admin/posts", ...)` 这种字面量。改为在启动时按当前路径生成，路径变更后靠**中间件在请求入口改写 `r.URL.Path`** —— 即把 `/myconsole/posts` 内部改写成 `/admin/posts` 再交给固定前缀的 mux。这样：
- 路由表只注册一次，无需重建
- 改路径只影响中间件的一行判断，零成本生效

| 4 | `tag` | 105 | 验证多对多中间表 |
| 5 | `banner` / `link` | 153 / - | 同构简单表 |
| 6 | `message` | 130 | 验证状态筛选与分页 |
| 7 | `page` | 122 | 验证 slug 唯一 |
| 8 | `media` | 96 | 验证文件路径拼接 |
| 9 | `category` | 180 | 验证自关联树（`ParentID` → `Children`） |
| 10 | `menu` | 198 | 验证两级结构（menu → items） |
| 11 | `post` | 494 | 最复杂：多条件筛选、标签关联、字段值、上下篇 |

### 3.3 Tailwind + Alpine

| # | 改动点 | 说明 |
| --- | --- | --- |
| 1 | 独立 Tailwind 构建 | `web/assets/src/input.css` + `tailwind.config.js`，输出到 `web/admin/static/app.css` |
| 2 | 设计令牌 | 用 Tailwind 的 `theme.extend.colors` 定义品牌色，替代 `:root` 变量 |
| 3 | 组件模板化 | 新建 `web/admin/templates/ui/*.html`，抽 `btn`/`input`/`table`/`pager`/`modal`/`badge`/`card` |
| 4 | 后台模板改造 | 18 个模板改 Tailwind 类名 |
| 5 | Alpine 接管交互 | 下拉菜单、模态框、批量选择、拖拽排序、主题切换 |

**为什么保留构建而非 CDN**：
- CDN 版（`cdn.tailwindcss.com`）是开发用的 JIT 运行时，官方明确不建议生产使用
- 生产需要 PurgeCSS 扫模板裁剪，否则体积 3MB+
- 构建产物约 20~30KB（gzip 后更小），且可离线部署

**构建集成**：`Makefile` 增加 `make assets`，产物提交进仓库，`make build` 不依赖 Node。

## 四、执行顺序

```
阶段一：可配置后台路径（独立、风险最低、见效最快）
   ↓ 验证：改路径后前后台均可访问，旧路径正确重定向
阶段二：GORM 迁移（逐个仓储替换，每步跑一次回归）
   ↓ 验证：全部 CRUD 通过，SQL 日志无 N+1
阶段三：Tailwind + 组件抽取（视觉层重做）
   ↓ 验证：18 个后台页面视觉回归，深浅色正常
```

**为什么这个顺序**：路径改造只动路由与模板变量，不碰数据层，先做能快速验证「重构方向可行」；GORM 迁移是纯内部替换，handler 不变；UI 改造最耗时且纯视觉，放最后避免与其他改动交叉影响。

## 五、风险与回滚

| 风险 | 应对 |
| --- | --- |
| GORM 迁移引入隐性行为差异（如零值更新） | 每个仓储迁移后跑对应 CRUD 回归；`Updates(map)` 显式指定字段，避免 `struct` 零值被忽略 |
| 路径改成不可猜测后自己进不去 | 保留旧路径重定向开关（默认开）；`.env` 可强制覆盖库中值 |
| Tailwind 构建产物与模板不一致 | `make assets` 纳入验收流程；`.gitignore` 不忽略产物，确保部署无需 Node |
| 改造期间站点不可用 | 每阶段结束提交一次，可单独 revert 对应 commit |

### 7.3 后台路径实现要点

```
.env ADMIN_PATH ──首次启动──> settings.admin_path ──后台修改──> 校验 → 落库 → 重建路由 → 跳新地址
                                      │
                                      └─ admin_path_legacy（最近 5 个历史路径，重启后仍然 302）
```

- **不改写 URL，改重建路由表**：`atomic.Value` 装载 `http.Handler`，`Reload()` 重新执行 `router.Build`。
  这样 handler 里 `r.URL.Path` 就是用户看到的路径，`next=` 参数、当前菜单高亮、模板链接都不会错位。
- **旧路径兼容必须注册裸路径**：只注册 `/admin/{rest...}` 时 ServeMux 会把 `/admin` 当子树根自动 307 补斜杠，
  多一跳。补上 `mux.Handle("GET /admin", ...)` 后才是直跳 302。
- **`admin_path_legacy` 不出现在设置页**：它是程序内部记录，已在 `Settings` handler 里过滤。

## 九、后台路径的补充加固（v1.1.1）

初版只做到「路径可改」，但没解决一个语义矛盾：**改路径的目的如果是隐藏后台，旧路径的 302 会亲手把新地址交出去。**

```
$ curl -I http://site/admin
HTTP/1.1 302 Found
Location: http://site/secret-entrance      ← 新入口直接写在响应头里
```

### 9.1 新增「旧路径静默」开关

设置项 `admin_path_silent`（系统设置 → 安全与入口）：

| 值 | 行为 | 说明 |
| --- | --- | --- |
| `0`（默认） | 旧路径 302 到新路径 | 书签友好，但泄露新入口 |
| `1` | 旧路径走 `h.NotFound` | 与任意不存在的页面**响应体、响应头完全一致**，无法指纹识别 |

实现上 `legacyRedirect` 每次请求读 `ap.Silent()`，改开关无需重建路由。

**实测**：

```
开启静默后
  /admin          404      ← 旧路径
  /manage         404
  /no-such-page   404      ← 对照
  /secret-entrance 303     ← 当前入口，仍可用（跳登录）

404 响应体 md5：/admin == /no-such-page  ✅ 完全一致
```

### 9.2 robots.txt 不再硬编码 `/admin/`

原实现把 `Disallow: /admin/` 写死（`front.go`），改路径后这条既没屏蔽真正的后台，又暴露了「这里原本是后台」。

更关键的是：**robots.txt 是公开文件，把后台路径写进 Disallow 等于向所有扫描器广播入口位置**。
所以第一版「动态列出所有历史路径」的做法其实更糟，最终策略改为：

| 模式 | robots.txt |
| --- | --- |
| 静默（隐藏后台） | 完全不写后台路径 —— 靠「不链接 + 未登录跳登录」防收录 |
| 非静默 | 只屏蔽当前路径，帮搜索引擎跳过；不列历史路径 |

### 9.3 顺带修复

- **`site_url` 与 `.env` 不一致**：库中是 `http://localhost:8095`，`.env` 是 8090，
  导致 `sitemap.xml` / `rss.xml` 输出错域名的绝对链接。已修正为 8090 并验证。

## 十、后台安全加固（v1.1.2）

### 10.1 先修地基：`ClientIP` 无条件信任代理头

**问题**：`utils.ClientIP` 一进来就读 `X-Real-IP` / `X-Forwarded-For`。这两个头任何客户端都能伪造，
后果是**所有基于 IP 的保护都会失效**——限流换个头就绕过，IP 白名单发个 `X-Forwarded-For: 10.1.2.3` 就进去了。

**修复**：新增 `TRUST_PROXY` 配置（默认 `0`），只有显式开启才读代理头，否则一律用 TCP 对端地址。

```
utils.SetTrustProxy(cfg.TrustProxy)   // main 启动时设置，早于任何取 IP 的代码
ClientIP(r):  trustProxy ? XFF 优先 : RemoteIP(r)
```

**实测**（白名单设为仅允许 `10.0.0.0/8` + `192.168.0.0/16`，本机 IP 是 `::1`）：

| 请求 | TRUST_PROXY=0 | TRUST_PROXY=1 |
| --- | --- | --- |
| 不带代理头 | 403 | 403 |
| `X-Forwarded-For: 10.1.2.3` | **403** ✅ | 200（信任代理头） |
| `X-Real-IP: 10.1.2.3` | **403** ✅ | 200 |

修复前这三行都会是 200 —— 白名单形同虚设。

### 10.2 后台 IP 白名单

新增 `internal/security/ipallow.go` + `internal/middleware/ipguard.go`。

| 设计点 | 说明 |
| --- | --- |
| 规则格式 | 单 IP、CIDR、`#` 注释，每行一条；空 = 不限制 |
| 作用范围 | 当前后台路径 + 历史路径 + 后台静态资源；**前台永远放行** |
| 热更新 | 规则存 `atomic.Pointer`，保存即生效，不重启不重建路由 |
| 自锁保护 | 新规则不含当前访问 IP 时**拒绝保存**并提示 |
| 格式校验 | 无法识别的行拒绝保存并列出，避免"以为生效其实没生效" |
| 拦截面 | 返回 403 并显示当前 IP（内网场景排查优先，不刻意伪装成 404） |

中间件位置：`WithAdminPath` 之后、`SessionMiddleware` 之前 —— 被拦的请求不该占用连接、也不该创建会话。

### 10.3 登录锁定补两个维度

原实现只有 `login:ip:username` 一个 key，换个 IP 就能继续打同一账号。现在三维度独立计数：

| key | 拦截场景 |
| --- | --- |
| `login:pair:<ip>:<user>` | 常规暴力破解 |
| `login:acct:<user>` | 分布式撞库 / 代理池换 IP 打同一账号 |
| `login:ip:<ip>` | 字典轮换用户名 |

**实测**：

```
第 1~5 次错误密码   → 「用户名或密码错误」
第 6 次起           → 「登录失败次数过多，请 15 分钟后再试」

全新会话 + 正确密码 → 仍被锁（按账号维度）
换一个不存在的账号  → 仍被锁（按 IP 维度）
```

### 10.4 顺带修复：限流器从未被清理

`Limiter.Cleanup()` 定义了但**没有任何地方调用**。加上按账号维度后，攻击者用大量随机用户名
可以让 map 无限增长。已在 main 起一个 5 分钟 ticker 定期清理，并由 `Handler.CleanupLimits()` 统一收口。

### 10.5 后台响应补 `X-Robots-Tag`

后台所有响应（含登录页）加 `X-Robots-Tag: noindex, nofollow, noarchive`，
与页面内的 `<meta name="robots">` 形成纵深防御。前台不受影响（实测前台该头数量为 0）。

### 10.6 一个反复踩到的坑

`admin_ip_allow` 第一次实现时，校验放在 `SetBatch(kv)` **之后** —— 结果非法值照样写进了库，
只是运行期没生效。这和之前 `admin_path` 的问题是同一个：

> **凡是"要先校验再落库"的设置项，必须在 `SetBatch` 之前从 `kv` 里摘出来。**

现在 `admin_path` 与 `admin_ip_allow` 都在 `SetBatch` 前 `delete`，校验通过后单独 `Set`。
测试也改成「校验被拒后，再查库确认值未被污染」，而不只看运行时行为。

## 十一、操作审计日志（v1.1.3）

前两轮做完路径与白名单后，剩下的最大缺口是：**改了什么、谁改的、什么时候改的，只留在终端日志里**。
终端日志会滚动、不落库、交接时无法查证。这一轮补齐。

### 11.1 表设计

`0002_audit_logs.sql`：

| 字段 | 用途 |
| --- | --- |
| `user_id` / `username` | 操作人（登录失败时无 ID，只有用户名） |
| `action` | 动作标识，`<对象>.<动词>`，如 `post.delete` |
| `target` | 操作对象，优先记名称（文章标题、栏目名），取不到才退回 ID |
| `detail` | 补充说明，**不记敏感值**（设置只记改了哪些键名） |
| `ip` | 操作来源 IP，走 `ClientIP`（已支持 TRUST_PROXY） |
| `created_at` | 时间，配 `idx_audit_created` 索引 |

### 11.2 埋点范围

| 分类 | 动作 |
| --- | --- |
| 认证 | `auth.login` / `auth.login_fail` / `auth.logout` |
| 安全 | `settings.admin_path`、`settings.ip_allow`、`settings.save` |
| 文章 | `post.create` / `post.update` / `post.delete` / `post.bulk` |
| 内容 | `page.*`、`category.*`、`tag.*`、`field.*`、`media.*` |
| 运营 | `banner.*`、`link.*`、`menu.*`、`message.*` |
| 系统 | `user.*`、`theme.switch`、`audit.purge` |

### 11.3 三个设计取舍

**1. 审计失败不能阻断业务**

`h.audit()` 内部把写库错误降级为 `slog.Warn`，不返回错误。审计是旁路，不能因为日志表写不进去就让用户发不了文章。

**2. 删除类操作要先取名称再删**

只记 ID 的话，半年后看日志完全不知道删的是什么。所有删除 handler 都在 `Delete` 之前查一次名称：

```go
pageTitle := ""
if old, err := h.repo.Page.ByID(id); err == nil { pageTitle = old.Title }
_ = h.repo.Page.Delete(id)
h.audit(r, AuditPageDelete, pageTitle, "单页 ID "+...)
```

**3. 设置只记键名，不记值**

设置里有短信密钥、邮件密码这类敏感项。`settings.save` 的 detail 只写 `site_name, site_url` 这样的键名列表，绝不写值。

### 11.4 登录场景的特殊处理

登录成功时 `middleware.UserFrom(r)` 还是 nil（Session 在库里更新了，但 context 没刷新），
用 `audit(r, ...)` 会丢 `user_id`。因此加了 `auditAs(r, userID, username, ...)`，
登录成功显式传 `u.ID`；登录失败没有 ID，传 0。

### 11.5 页面与权限

- 路径：`GET /{admin}/audits`，`POST /{admin}/audits/purge`
- 权限：`authAdmin`（仅 admin），侧栏链接包在 `{{if .User.IsAdmin}}` 内
- 筛选：操作人、动作类型（下拉由 `DistinctActions` 动态生成）、关键字（对象/说明）
- 分页：翻页链接携带筛选参数，否则翻页丢条件
- 保留：180 天，main 里每小时检查清理一次；也可在页面上手动清理

### 11.6 顺手加的小功能

后台路径输入框旁加了「随机生成」按钮，一键产生 `manage-x7k2v` 这类不可猜测的路径（Alpine 实现，无后端改动）。
人手起名容易起成 `admin2`、`manage` 这种，随机生成的熵高得多。

## 十二、高危操作二次验证（v1.1.4）

### 12.1 为什么要做

后台路径与 IP 白名单有个共同特征：**改错就把自己关在门外**。
它们原来的保护只有「已登录会话」——这意味着：

- 会话被劫持（XSS、共享电脑没退出）→ 攻击者可以改路径把真正的管理员挤出去
- 管理员自己在别人电脑上忘了退出 → 同上
- 手滑把白名单写成 `10.0.0.0/8` 而自己不在内网 → 被代码拦住了（有自锁保护），但如果写的是宽泛但不对的网段呢

二次验证把「有会话」升级成「有会话 + 知道密码」，成本极低，收益明确。

### 12.2 触发条件（关键设计）

不是整个「安全与入口」分组都要求密码，只有**实质变更**才要求：

| 场景 | 是否要求密码 |
| --- | --- |
| 改了 `admin_path`，值合法且与当前不同 | ✅ 要求 |
| `admin_path` 填了非法值（如 `a`） | ❌ 不要求（后面会直接报错，先要密码只会让人困惑） |
| `admin_path` 与当前值相同 | ❌ 不要求 |
| 改了 `admin_ip_allow`，规范化后与库中不同 | ✅ 要求 |
| 只勾选/取消 `admin_path_silent` | ❌ 不要求 |
| 改其他分组任意设置 | ❌ 不要求 |

白名单比较用**规范化后的规则集合**（去注释、去空行、排序），
否则「只是加了个 `# 注释`」或「调换两行顺序」也会触发密码框，很烦。

### 12.3 实现

后端 `internal/handler/reauth.go`：

```go
if h.needReauth(r, hasAdminPath, rawAdminPath, hasIPAllow, rawIPAllow) {
    if msg := h.checkReauth(r); msg != "" {
        h.redirect(..., msg); return
    }
    h.audit(r, AuditReauthOK, "security", "修改安全项已通过密码验证")
}
```

`checkReauth` 做了三件事：

1. 复用登录限流器（key = `reauth:<ip>`，5 次 / 15 分钟），防止有人拿已登录会话当跳板暴力猜密码
2. `bcrypt` 校验当前账号密码（`security.CheckPassword`）
3. 成功时 `Reset` 该 IP 的计数

前端在 security 分组渲染一个默认隐藏的密码卡片（Alpine `x-show="danger"`），
`admin_path` 输入框与 `admin_ip_allow` 文本域被修改时 `danger = true`，卡片展开并给密码框加 `:required`。

### 12.4 实测

| 用例 | 结果 |
| --- | --- |
| 改路径，不带密码 | 拒绝，库中路径不变 |
| 改路径，密码错误 | 拒绝，提示「当前密码不正确，修改未生效」 |
| 改路径，密码正确 | 成功，跳到新地址 |
| 改普通设置（site_name），不带密码 | **成功**（不要求） |
| 改白名单，不带密码 | 拒绝 |
| 改白名单，密码正确 | 成功 |
| 连续多次密码错误 | 提示「密码验证失败次数过多，请稍后再试」 |

审计同步记录：

```
settings.reauth_fail | security | 未提供密码
settings.reauth_fail | security | 密码错误
settings.reauth_ok   | security | 修改安全项已通过密码验证
settings.admin_path  | vault77  | 由 /admin 改为 /vault77
```

**失败也记日志**——如果有人正在尝试借会话改后台入口，日志里能看到连续失败。

### 12.5 一个自己踩的坑

给 `admin_path` 输入框加 `@input` 时，用 Python 做了 `replace(old, new, 1)`，
但 `old` 这行和前面 `image` 类型设置项的输入框**完全一样**（同类名、同属性、同缩进），
结果 `@input` 加到了图片设置项上，`admin_path` 那行没动。

表现是：截图里改路径后密码框不展开，控制台无报错，诊断脚本显示 `danger` 始终为 false。

教训：**模板里做字符串替换，锚点必须带足够上下文**（拿到后面紧跟的 `gen()` / `pickImage()` 才能区分）。
现在两处 `@input` 都用完整上下文块替换，并加了验证脚本确认落点。

## 十三、「还看得到 admin」的全面排查（v1.1.5）

用户反馈：路径能改了，但界面上仍能看到 `admin`。做了一次地毯式排查——
把后台路径改成 `manage`，抓下全部页面 HTML，逐处检出 `admin` 出现的上下文。

**方法**：`curl` 抓 17 个后台页面 → 用 Python 正则定位每处 `admin` 前后 40 字符 → 人工分类。

### 13.1 排查结论

| 出现位置 | 性质 | 处理 |
| --- | --- | --- |
| URL / 链接 / 表单 action | 已经是 `/manage/...` | ✅ 无问题 |
| `assets/admin.js` | 资源**文件名**含 admin | 🔧 改名 `app.js` |
| `app.js` 里 `\|\| '/admin'` | 路径兜底猜测 | 🔧 去掉，缺失时明确报错 |
| `data-admin-path` | HTML 属性名 | 🔧 改名 `data-base-path` |
| `localStorage['admin-theme']` | 主题偏好键 | 🔧 改 `gocms-theme`，双读兼容旧键 |
| `postFormURL()` 返回 `/admin/...` | 函数内部拼接 | 🔧 改 `h.adminPath()` |
| 设置页文案「如 `/admin`」 | 硬编码举例 | 🔧 改为动态渲染真实历史路径 |
| 顶栏用户名 `admin` | 账号数据 | 保留（是数据不是硬编码） |
| 角色值 `value="admin"` | RBAC 标识 | 保留 |
| 审计日志内容 | 历史记录 | 保留 |
| `setting_admin_path` 等 name/id | 设置项 key（数据库列名） | 保留（改动需数据迁移，且不可见） |

### 13.2 改完后的实测（路径 = `manage`）

每页只剩 2 处 `admin`，且都不是路径：

```
1. localStorage.getItem('admin-theme')   ← 兼容旧键的 fallback 读取（有意保留）
2. <strong>admin</strong>                 ← 登录用户名
```

设置页额外出现 `setting_admin_path` 等（表单 name/id）与动态渲染的历史路径。
审计页出现的是日志内容（用户名、动作名、`由 /admin 改为 /manage`）。

### 13.3 顺带修的隐患

`postFormURL(id)` 原来直接返回 `"/admin/posts/..."`。
虽然所有调用点都经过 `h.redirect()`（内部有 `rebase()` 兜底），
但**一旦有人把这个返回值塞进模板**，就会变成写死的 `/admin`。已改成方法并走 `h.adminPath()`。

`app.js` 的路径兜底 `getAttribute('data-admin-path') || '/admin'` 同理：
属性缺失时猜一个默认值，只会在改过路径后把上传请求打到 404，反而更难排查。现在缺失即提示。

### 13.4 开发脚本也参数化

`scripts/audit-admin-ui.js`、`scripts/shot-reauth.js` 原本写死 `/admin`，改路径后跑不了。现在支持：

```bash
ADMIN_PATH=manage node scripts/audit-admin-ui.js
```

默认仍取 `admin`，不设环境变量时行为不变。
